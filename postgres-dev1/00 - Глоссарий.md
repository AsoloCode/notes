# DEV1-16 — Глоссарий

> [!note] ➕ Дополнено агентом (не из курса)
> Раздел собран по открытым источникам (документация PostgreSQL, статьи) для быстрого
> повторения. Формулировки сверены с офиц. документацией; в самом курсе этих определений в явном виде нет.

### MVCC (многоверсионность)
Несколько версий строки хранятся рядом; каждой транзакции показывается согласованный снимок.
Писатели не блокируют читателей. Версии помечаются служебными полями `xmin`/`xmax`.

### xmin / xmax
`xmin` — номер транзакции, создавшей версию строки; `xmax` — номер транзакции, удалившей/обновившей
её (0 — версия актуальна). Основа видимости строк в MVCC.

### WAL (Write-Ahead Log)
Журнал упреждающей записи: перед изменением страницы её изменение пишется в WAL и сбрасывается
(`fsync`). Обеспечивает durability и используется для PITR и репликации. Адресуется позицией LSN.

### Checkpoint (контрольная точка)
Момент, когда все «грязные» страницы из `shared_buffers` сброшены на диск, а WAL до этой точки
можно переиспользовать (`full_page_writes` защищает от torn pages). Частые checkpoint'ы снижают
«пик» записи после сбоя, но нагружают I/O.

### Страница, heap tuples, FILLFACTOR, HOT
Данные хранятся страницами по 8 КБ. `FILLFACTOR` резервирует место под обновления. HOT-обновление
(`HEAP ONLY TUPLE`) не трогает индексы, если изменились только неиндексируемые столбцы.

### TOAST (The Oversized Attribute Storage Technique)
Большие значения атрибутов режутся на фрагменты и хранятся в отдельной TOAST-таблице (схема
`pg_toast`). Читается только при обращении к длинному столбцу.

### MVCC-уровни изоляции (Read Committed, Repeatable Read, Serializable)
`Read Committed` (по умолчанию) — снимок на каждый запрос; `Repeatable Read` — снимок на транзакцию,
ловят write-skew не всегда; `Serializable` (SSI) — как Repeatable Read + отслеживание конфликтов
сериализации.

### PL/pgSQL
Процедурный язык Postgres: переменные, ветвления, циклы, обработка исключений (`EXCEPTION`,
`SQLSTATE`), курсоры, `EXECUTE` для динамического SQL.

### VOLATILE / STABLE / IMMUTABLE
Классификация функций для планировщика: `IMMUTABLE` — результат зависит только от аргументов
(можно сворачивать); `STABLE` — не меняется внутри запроса; `VOLATILE` — может менять состояние
(вызывается на каждую строку). Влияет на индекс и inlining.

### Триггеры
Функции, вызываемые на `INSERT/UPDATE/DELETE` — `BEFORE`/`AFTER`/`INSTEAD OF`, `FOR EACH ROW` или
`STATEMENT`. Осторожно с производительностью: срабатывают на каждую изменяемую строку.

### Курсоры, EXECUTE, SQLSTATE
Курсор открывается и читается порциями (`FETCH`) — экономит память на больших выборках. `EXECUTE`
выполняет динамический SQL с параметрами (`USING`). `SQLSTATE` — стандартный код ошибки для `EXCEPTION`.

### Составные типы и массивы
Массивы (`int[]`, `ANY`) и составные типы (`ROW(...)`, пользовательские) позволяют хранить
структурированные значения в одном столбце; для полуструктурированных данных — `jsonb`.

### Логическое резервирование
`pg_dump`/`pg_restore` выгружают объекты и данные в переносимом виде (в отличие от физического
копирования). Логическая репликация публикует изменения по таблицам через слоты.
