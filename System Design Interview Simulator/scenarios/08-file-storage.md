# Сценарий 8 — Файловое хранилище

> [!abstract] Бриф
> Спроектируйте облачное файловое хранилище (Dropbox-подобное): загрузка и скачивание файлов,
> синхронизация между устройствами, дедупликация и шаринг с правами доступа.

## Что дано (функциональные требования)

- Загрузка/скачивание файлов, в т.ч. больших (гигабайты).
- Синхронизация между устройствами пользователя.
- Версионирование файлов и восстановление.
- Шеринг файлов/папок с правами (чтение/запись).

## Нефункциональные требования (даны частично)

- Durability данных — критична (не терять файлы).
- Большие объёмы и большие файлы: важна дедупликация и докачка.
- Метаданные синхронизации могут быть eventually consistent.

> [!question] Вопросы интервьюера на старте
> 1. Сколько пользователей, средний и максимальный размер файла?
> 2. Нужна ли реальная дедупликация блоков между пользователями?
> 3. Как разрешаем конфликты синхронизации?

## Ваша попытка — заполните разделы

Запишите ответ письменно (например, в `attempts/08-file-storage.md`). Раскройте:

1. **Уточняющие вопросы** — размеры файлов, dedup, конфликты, шеринг.
2. **Оценка нагрузки** — объём загрузок/сутки, средний файл, объём хранения, трафик.
3. **API** — upload (chunked), download, list/versions, share/ACL, sync deltas.
4. **Модель данных** — file, version, chunk/block, ACL, device cursor.
5. **Архитектура** — API/metadata service + block storage (S3) + sync service.
6. **Масштабирование** — шардинг метаданных, CDN, партиции по пользователю.
7. **Отказоустойчивость** — durability (репликация блоков), докачка, восстановление.
8. **Consistency** — метаданные vs блоки, версии, конфликты sync.
9. **Bottlenecks** — большие файлы, горячие популярные файлы при шеринге.
10. **Trade-offs** — dedup vs latency, sync protocol (delta vs full), CDN.
